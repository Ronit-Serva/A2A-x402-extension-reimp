# M6 — PASS, failure recovery

`npm run m6:check` passed the actual transaction/fault matrix on 2026-10-25;
`npm run m6:reset-check` passed after an actual Hardhat process restart.
`M6-result.json` contains transaction identities and observed transfer events.

The matrix covers concurrent duplicates and changed body/payer/payment
association rejection; no cached result disclosure without proof; lost
settlement response; a real pending transaction with mining paused; server
restart after settlement; missing-gas failure; a paid service exception;
facilitator crash between broadcast and hash persistence reconciled from
AuthorizationUsed/Transfer logs; and lost result response recovered after
server restart. Seven successful payment events were observed across these
independent scenarios. Each successful scenario charged once.

Hardhat 3 does not support `hardhat_reset` in this installation. Reset checks
therefore restart the real node process. Old manifests/services are rejected;
the M7 reuse check also verifies the block anchor after deterministic addresses
and bytecode are reused. State files are namespaced by the deployment anchor.

EIP-3009 signs token transfer terms, not the A2A body. Body/payment association
is enforced by durable application records. The service is deterministic and
has no external side effects. A crash between physical computation and result
persistence may repeat that computation; the implementation records one logical
result and does not claim arbitrary physical exactly-once execution. A paid
service exception remains paid-undelivered, with no automatic refund or fresh
authorization. Unknown settlement stays unknown until chain reconciliation
proves an outcome. Fault hooks require LOCAL_FAULTS=1 and are enabled only in
the recovery harness.
